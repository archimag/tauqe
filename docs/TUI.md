# TUI

## 1. Назначение

TUI (`tauqe-tui`) — первый полноценный клиент системы.

TUI является:
- эталонной реализацией (reference implementation) клиента протокола;
- реальным рабочим интерфейсом разработчика;
- визуально плотным и компактным;
- строго **keyboard-first**;
- построенным на стыке философии **Magit** (интерфейс живого структурированного состояния) и **SLIME** (семантический презентационный протокол).

TUI общается с сервером **исключительно по протоколу JSON-RPC через stdio**.

## 2. Основной UX принцип: Проект как состояние, а не чат

TUI представляет проект как **живое структурированное состояние**.
Разговор с моделью оформлен как структурированный **org-mode / outline документ** с независимыми сворачиваемыми секциями.

## 3. Структура ответа модели (Org-Mode Turn Structure)

Ответ модели в рабочей области состоит из чётко разделённых сворачиваемых блоков:

```text
[+] Reasoning (~180 tokens, Ctrl+R to toggle)

Я обновлю валидацию путей в контекст-менеджере и добавлю обработку ошибок:

[COMMITTED: a1b2c3d] Proposed Edits (2/2 files) - [ / ] Navigate, Space/Enter to Fold/Unfold | Press 'u' to Undo AI commit
  ● ▼ [EDIT] crates/core/src/context.rs (1 hunk) ✓
      @@ hunk 1 @@
      - old_check();
      + new_check();
      + validate_path();
    ▶ [NEW] crates/core/src/edits/validator.rs (1 hunk) ✓

Tokens: 1250 prompt, 310 completion, 180 reasoning | Operation cost: $0.00421
Session total cost: $0.01850
```

### 3.1 Блок Reasoning
- Отображает ход рассуждений модели.
- Автоматически скрывается при начале вывода основного текста/кода для экономии экрана.
- В любой момент разворачивается и сворачивается по `Ctrl+R`.

### 3.2 Текстовый комментарий
- Чистые абзацы текста модели, отрендеренные через Markdown (заголовки, списки, inline-код, таблицы).
- Без сырых XML-тегов, маркеров диффов или служебных символов.

### 3.3 Интерактивный блок правок (Proposed Edits)
- Появляется на лету, как только модель начинает предлагать изменения.
- Отображает компактный список затронутых файлов.
- Для каждого файла отображается бейдж операции (`[NEW]`, `[DEL]`, `[EDIT]`), число чанков и статус валидации в реальном времени:
  - Спиннер (`⠋`, `⠙`, `⠹`...) во время генерации чанков;
  - Бейдж повторной попытки при ошибке поиска (`(Retrying 1/3: NoMatch...)`);
  - Зелёная галочка `✓` после успешной валидации чанков в памяти;
  - Красный крестик `✗` с текстом ошибки при окончательном сбое.
- Общий статус применения:
  - `[Modifying]` — во время генерации;
  - `[APPLIED]` — после успешного применения правок к файлам;
  - `[COMMITTED: hash]` — после успешной фиксации изолированного AI-коммита;
  - `[REJECTED]` — при ошибке или отмене правок.

## 4. Интерактивная навигация по правкам

- Клавиши `[` и `]` (или стрелки `↑`/`↓` при пустом поле ввода) перемещают селектор по списку файлов.
- Клавиша `Tab` (а также `Space` или `Enter` при пустом поле ввода) сворачивает и разворачивает секции, группы и unified diff выбранного файла в стиле Magit/Org-mode.
- Удалённые строки подсвечиваются красным (`-`), добавленные — зелёным (`+`).

## 5. Многострочный ввод намерений (Multi-line Intent Editor)

Поле ввода адаптировано для написания подробных запросов и пакетной вставки фрагментов кода:
- **Динамическое расширение (Auto-grow):** блок ввода увеличивается по высоте от 3 строк до 40% высоты экрана по мере набора текста.
- **Внутренний скроллинг:** при превышении лимита включается внутренний скролл с автосопровождением строки курсора.
- **Разделение ввода и отправки:**
  - `Enter` (а также `Ctrl+Enter` / `Alt+Enter`): отправка запроса модели;
  - `Shift+Enter` и `Ctrl+J`: вставка новой строки (`\n`);
  - `Tab`: вставка 2 пробелов отступа (если в поле есть текст).
- **Emacs-стиль редактирования текста:**
  - `Ctrl+A` / `Ctrl+E` — переход в начало / конец текущей строки;
  - `Alt+B` / `Alt+F` — перемещение курсора на слово назад / вперёд;
  - `Ctrl+K` — удаление текста от курсора до конца строки в kill-ring;
  - `Ctrl+U` — удаление текста от курсора до начала строки;
  - `Alt+D` / `Alt+Backspace` — удаление слова вперёд / назад;
  - `Ctrl+Y` — вставка (yank) из kill-ring.

## 6. Безопасные подтверждения деструктивных операций

### 6.1 Откат изменений (Undo AI Commit)
- Нажатие `u` при пустом поле ввода открывает модальное окно подтверждения (`Confirm Undo`).
- В окне отображается хеш коммита, саммари и предупреждение о восстановлении незакоммиченных изменений разработчика из чекпоинта.
- Подтверждение: `y` / `Y` или `Enter`.
- Отмена: `n` / `N` или `Esc`.
- Во время активной генерации операция Undo блокируется.

### 6.2 Очистка истории сессии (Clear History)
- Нажатие `Ctrl+L` открывает модальное окно подтверждения (`Confirm Clear History`).
- Предупреждает о безвозвратном удалении файла истории `.tauqe/history.jsonl` и очистке вывода экрана.
- Подтверждение: `y` / `Y` или `Enter`.
- Отмена: `n` / `N` или `Esc`.
- Во время активной генерации очистка блокируется.

## 7. Экраны TUI

Переключение экранов осуществляется строго по `Ctrl+1` / `Ctrl+2` / `Ctrl+3`:

1. **Model View (`1: Model`):**
   - Верхняя панель: статус репозитория (ветка, HEAD, clean/dirty), текущий воркфлоу `Wf`, протокол `Proto`, активная модель `Model`, стоимость сессии (`Session`) и последнего запроса (`Last`).
   - Рабочая область текущего ответа в org-mode формате со счётчиком скролла.
   - Многострочное поле ввода намерений (Intent).
   - Футер подсказок горячих клавиш.

2. **Context View (`2: Context`):**
   - Сводка токенов контекста, количества файлов и ревизии `#N`.
   - Список файлов с бейджами `[READ-ONLY]` и `[EDITABLE]`.
   - Быстрые клавиши:
     - `Tab` / `Enter` — открыть / свернуть предпросмотр содержимого выбранного файла;
     - `e` — добавить редактируемый файл (`EDITABLE`);
     - `r` / `a` — добавить файл только для чтения (`READ-ONLY`);
     - `t` — переключить режим доступа файла (Editable ↔ Read-only);
     - `d` / `x` — удалить файл из контекста.

3. **History View (`3: History`):**
   - Хронологический просмотр семантической истории диалога (`[USER]`, `[ASSISTANT]`, `[SYSTEM]`, `[UNDO]`) с ID записей, хешами коммитов и затронутыми файлами.
   - `Tab` / `Enter` — развернуть / свернуть подробности выбранного хода (промпт, ответ, список правок).
   - Динамическая подгрузка предыдущих ходов при скролле вверх (`↑` / `k` / `PgUp`).
   - Умный скролл: сохранение позиции при чтении старых записей и автоскролл внизу (`Auto-scroll: ON/OFF`).

## 8. Горячие клавиши (Keybindings)

### Общие
```text
Ctrl+1        Переключиться в Model View
Ctrl+2        Переключиться в Context View (сохраняет набранный текст ввода)
Ctrl+3        Переключиться в History View
Ctrl+W        Выбор Workflow через диалог (toolchain, git, naive)
Ctrl+P        Выбор Edit Protocol через диалог (xml, structured)
Ctrl+M        Выбор активной модели через диалог
Ctrl+C        Прерывание активной генерации модели (Cancel)
Ctrl+L        Очистка экрана и истории сессии разговора (с подтверждением Y/N)
?             Модальное окно справки (Help)
Esc           Очистить ввод / закрыть модальное окно / отмена
```

### В Model View (Редактор ввода)
```text
Enter         Отправить запрос модели (также Ctrl+Enter / Alt+Enter)
Shift+Enter   Вставить перевод строки \n (также Ctrl+J)
← / →         Перемещение курсора влево / вправо
↑ / ↓         Перемещение курсора вверх / вниз по строкам текста
Ctrl+A / E    Переход в начало / конец строки
Alt+B / F     Перемещение на слово назад / вперёд
Ctrl+K / U    Удалить до конца / начала строки в kill-ring
Alt+D / Alt+Bksp Удалить слово вперёд / назад
Ctrl+Y        Вставить (yank) удалённый текст из kill-ring
Tab           Вставить 2 пробела отступа
```

### В Model View (Навигация при пустом вводе)
```text
Tab / Space   Свернуть / развернуть секцию, группу или unified diff выбранного файла
[ / ]         Переход вверх / вниз по списку затронутых файлов
u             Откатить последний AI-коммит (открывает подтверждение)
Ctrl+R        Показать / скрыть ход рассуждений (Reasoning)
PgUp / PgDn   Постраничная прокрутка вывода
Home / End    Переход в самое начало / в самый конец вывода
```

### В Context View
```text
↑ / ↓ (k / j) Навигация по файлам контекста
Tab / Enter   Открыть / закрыть просмотр содержимого выбранного файла
e             Добавить файл / паттерн для РЕДАКТИРОВАНИЯ (Editable)
r / a         Добавить файл / паттерн для ЧТЕНИЯ (Read-Only)
t             Переключить режим доступа файла (Editable ↔ Read-Only)
d / x / Del   Удалить файл из контекста
```

### В History View
```text
↑ / ↓ (k / j) Навигация по записям истории
Tab / Space   Развернуть / свернуть детали выбранной записи истории
PgUp / PgDn   Постраничная прокрутка
Home / End    Переход в самое начало / в самый конец
```

## 9. Инвариант: отсутствие arbitrary shell

TUI не предоставляет терминального шелла для модели. Модель может предлагать только точечные правки в разрешённые файлы и запускать стандартную проверку тулчейна (`cargo check`, `npm test` и т.д.).
