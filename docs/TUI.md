# TUI

## 1. Назначение

TUI — первый полноценный client системы.

Это не временный CLI и не стандартный веб-чат.

TUI должен быть:

- reference implementation protocol;
- реальным рабочим интерфейсом;
- достаточно удобным для self-hosting разработки;
- визуально плотным;
- keyboard-first;
- voice-first по вводу intent;
- построенным на стыке философии **Magit** (интерфейс живого состояния) и **SLIME** (семантический презентационный протокол).

Он общается с server **только через protocol**.

## 2. Основной UX принцип: Проект как состояние, а не чат

TUI представляет проект как **живое структурированное состояние**.
Разговор с моделью не раздувается в бесконечную простыню текста. Каждый ход модели (turn) оформлен как структурированный **org-mode / outline документ**.

## 3. Структура ответа модели (Org-Mode Turn Structure)

Ответ модели в рабочей области состоит из четко разделенных сворачиваемых блоков:

```text
[+] Reasoning (~180 tokens, Ctrl+R to toggle)

Я обновлю валидацию путей в контекст-менеджере и добавлю обработку ошибок:

[APPLIED] Proposed Edits (2/2 files) - [ / ] Navigate, Space/Enter to Fold/Unfold
  ● ▼ [EDIT] crates/core/src/context.rs (1 hunk) ✓
      @@ hunk 1 @@
      - old_check();
      + new_check();
      + validate_path();
    ▶ [NEW] crates/core/src/edits/validator.rs (1 hunk) ✓

Usage: prompt 1250 tokens, completion 310 tokens, cost $0.00421
```

### 3.1 Блок Reasoning
- Отображает ход мыслей модели.
- По умолчанию автоматически сворачивается при начале генерации текста/кода для экономии экрана.
- В любой момент разворачивается и сворачивается по `Ctrl+R`.

### 3.2 Текстовый комментарий
- Чистые абзацы естественного языка модели.
- Никаких сырых XML-тегов, маркеров дифов или служебных символов.

### 3.3 Интерактивный блок правок (Proposed Edits)
- Появляется на лету, как только модель начинает предлагать изменения.
- Отображает компактный список затронутых файлов.
- Для каждого файла отображается бейдж операции (`[NEW]`, `[DEL]`, `[EDIT]`), число чанков и статус валидации в реальном времени:
  - Спиннер (`⠋`, `⠙`, `⠹`...) во время генерации чанков;
  - Зеленая галочка `✓` после успешной валидации чанков в памяти;
  - Красный крестик `✗` с текстом ошибки при сбое валидации (`NoMatch`, `AmbiguousMatch`).
- Общий статус применения: `[Modifying]` во время работы, `[APPLIED]` после атомарной записи на диск, `[REJECTED]` при ошибке.

## 4. Интерактивная навигация по правкам

Пользователю не нужно листать терминал вручную:
- Клавиши `[` и `]` (или стрелки `↑`/`↓` при пустом поле ввода) перемещают селектор по затронутым файлам.
- Клавиша `Space` или `Enter` сворачивает и разворачивает unified diff выбранного файла.
- В развернутом виде удаленные строки подсвечиваются красным (`-`), добавленные — зелёным (`+`).

## 5. Визуальная модель экранов

Переключение между экранами осуществляется по клавише `Tab`:

1. **Model View (`1: Model`):**
   - Заголовок репозитория (ветка, HEAD, clean/dirty, версия протокола).
   - Рабочая область текущего ответа/сессии в org-mode формате.
   - Поле ввода намерений (Intent).
   - Информативный футер горячих клавиш.

2. **Context View (`2: Context`):**
   - Полная сводка токенов контекста и ревизии.
   - Список файлов в контексте с бейджами `[READ-ONLY]` и `[EDITABLE]`.
   - Быстрые клавиши изменения прав:
     - `a` — модальный пикер с автодополнением по файлам репозитория;
     - `e` — сделать файл редактируемым;
     - `r` — сделать файл только для чтения;
     - `d` / `x` — удалить файл из контекста.

## 6. Горячие клавиши (Keybindings)

### Общие
```text
Tab           Переключение между Model и Context view
?             Модальное окно справки (Help)
Ctrl+C        Прерывание генерации модели (Cancel)
Ctrl+L        Очистка экрана и истории сессии
Esc           Отмена / закрытие модальных окон
```

### В Model View
```text
Enter         Отправить запрос / Развернуть выбранный diff
Space         Свернуть / развернуть diff под курсором
[ / ]         Переход вверх/вниз по списку затронутых файлов
Ctrl+R        Показать / скрыть рассуждения модели (Reasoning)
PgUp / PgDn   Постраничная прокрутка вывода
```

### В Context View
```text
↑ / ↓ (k / j) Навигация по файлам контекста
a             Открыть модальный поиск и добавление файла
e             Переключить в EDITABLE
r             Переключить в READ-ONLY
d / x         Удалить файл из контекста
```

## 7. Никакого arbitrary agent shell в TUI

TUI не создает иллюзии терминального доступа агента к системе. Модель может предлагать только точечные правки в разрешенные файлы и запрашивать запуск зарегистрированных `ProjectAction`.
