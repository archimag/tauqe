# TUI

## 1. Назначение

TUI — первый полноценный client системы.

Это не временный CLI и не стандартный веб-чат.

TUI должен быть:

- reference implementation protocol;
- реальным рабочим интерфейсом;
- достаточно удобным для self-hosting разработки;
- визуально плотным;
- keyboard-first;
- voice-first по вводу intent;
- построенным на стыке философии **Magit** (интерфейс живого состояния) и **SLIME** (семантический презентационный протокол).

Он общается с server **только через protocol**.

## 2. Основной UX принцип: Проект как состояние, а не чат

TUI представляет проект как **живое структурированное состояние**.
Разговор с моделью не раздувается в бесконечную простыню текста. Каждый ход модели (turn) оформлен как структурированный **org-mode / outline документ**.

## 3. Структура ответа модели (Org-Mode Turn Structure)

Ответ модели в рабочей области состоит из четко разделенных сворачиваемых блоков:

```text
[+] Reasoning (~180 tokens, Ctrl+R to toggle)

Я обновлю валидацию путей в контекст-менеджере и добавлю обработку ошибок:

[COMMITTED: a1b2c3d] Proposed Edits (2/2 files) - [ / ] Navigate, Space/Enter to Fold/Unfold | Press 'u' to Undo AI commit
  ● ▼ [EDIT] crates/core/src/context.rs (1 hunk) ✓
      @@ hunk 1 @@
      - old_check();
      + new_check();
      + validate_path();
    ▶ [NEW] crates/core/src/edits/validator.rs (1 hunk) ✓

Tokens: 1250 prompt, 310 completion, 180 reasoning | Operation cost: $0.00421
Session total cost: $0.01850
```

### 3.1 Блок Reasoning
- Отображает ход мыслей модели.
- По умолчанию автоматически сворачивается при начале генерации текста/кода для экономии экрана.
- В любой момент разворачивается и сворачивается по `Ctrl+R`.

### 3.2 Текстовый комментарий
- Чистые абзацы естественного языка модели.
- Никаких сырых XML-тегов, маркеров дифов или служебных символов.

### 3.3 Интерактивный блок правок (Proposed Edits)
- Появляется на лету, как только модель начинает предлагать изменения.
- Отображает компактный список затронутых файлов.
- Для каждого файла отображается бейдж операции (`[NEW]`, `[DEL]`, `[EDIT]`), число чанков и статус валидации в реальном времени:
  - Спиннер (`⠋`, `⠙`, `⠹`...) во время генерации чанков;
  - Зеленая галочка `✓` после успешной валидации чанков в памяти;
  - Красный крестик `✗` с текстом ошибки при сбое валидации (`NoMatch`, `AmbiguousMatch`).
- Общий статус применения:
  - `[Modifying]` — во время работы модели;
  - `[APPLIED]` — после успешного применения правок;
  - `[COMMITTED: hash]` — после успешной фиксации изолированного AI-коммита;
  - `[REJECTED]` — при ошибке или отклонении правок.

## 4. Интерактивная навигация по правкам

Пользователю не нужно листать терминал вручную:
- Клавиши `[` и `]` (или стрелки `↑`/`↓` при пустом поле ввода) перемещают селектор по затронутым файлам.
- Клавиша `Space` или `Enter` (при пустом поле ввода) сворачивает и разворачивает unified diff выбранного файла.
- В развернутом виде удаленные строки подсвечиваются красным (`-`), добавленные — зелёным (`+`).

## 5. Многострочный ввод намерений (Multi-line Intent Editor)

Поле ввода адаптировано для написания подробных запросов и вставки фрагментов кода:
- **Динамическое расширение (Auto-grow):** блок ввода плавно увеличивается по высоте от 3 строк до 40% высоты экрана по мере добавления текста.
- **Внутренний скроллинг:** если текст превышает лимит расширения, включается внутренний вертикальный скролл с гарантированной видимостью строки с курсором.
- **Разделение ввода и отправки:**
  - `Ctrl+Enter` (а также кросс-терминальный `Alt+Enter`): отправка запроса модели;
  - `Enter` и `Ctrl+J`: вставка новой строки (`\n`);
  - `Tab`: вставка 2 пробелов отступа (если в поле есть текст).
- **Emacs-стиль редактирования текста:**
  - `Ctrl+A` / `Ctrl+E` — переход в начало / конец текущей строки;
  - `Alt+B` / `Alt+F` — перемещение курсора на слово назад / вперед;
  - `Ctrl+K` — удаление (kill) текста от курсора до конца строки в kill-ring;
  - `Ctrl+U` — удаление текста от курсора до начала строки;
  - `Alt+D` / `Alt+Backspace` — удаление слова вперед / назад;
  - `Ctrl+Y` — вставка (yank) из kill-ring.

## 6. Безопасный откат изменений (Undo AI Commit)

- Нажатие клавиши `u` при пустом поле ввода открывает **модальное окно подтверждения** (`Confirm Undo`).
- В окне отображается хэш отменяемого коммита, его саммари и предупреждение о восстановлении незакоммиченных изменений разработчика из чекпоинта.
- Подтверждение: `y` / `Y` или `Enter`.
- Отмена: `n` / `N` или `Esc`.
- Во время активной генерации операция Undo блокируется.

## 7. Визуальная модель экранов

Переключение между экранами осуществляется по клавишам `Ctrl+1` / `Ctrl+2` (или `Tab` при пустом поле ввода):

1. **Model View (`1: Model`):**
   - Верхняя панель: статус репозитория (ветка, HEAD, clean/dirty), текущий `Wf` (Workflow), `Proto` (Edit Protocol), расходы за сессию (`Session`) и последний запрос (`Last`).
   - Рабочая область текущего ответа/сессии в org-mode формате со счетчиком скролла.
   - Многострочное поле ввода намерений (Intent).
   - Информативный футер горячих клавиш.

2. **Context View (`2: Context`):**
   - Полная сводка токенов контекста, количества файлов и ревизии `#N`.
   - Список файлов в контексте с бейджами `[READ-ONLY]` и `[EDITABLE]`.
   - Быстрые клавиши:
     - `a` — модальный пикер с автодополнением по файлам и glob-маскам (например, `*.rs`, `src/`);
     - `e` — сделать файл редактируемым (`EDITABLE`);
     - `r` — сделать файл только для чтения (`READ-ONLY`);
     - `d` / `x` — удалить файл из контекста.

## 8. Горячие клавиши (Keybindings)

### Общие
```text
Ctrl+1        Переключиться в Model View
Ctrl+2        Переключиться в Context View (сохраняет набранный текст ввода)
Tab           Переключение между Model и Context view (когда поле ввода пустое)
Ctrl+W        Циклическое переключение Workflow (toolchain -> git -> naive)
Ctrl+P        Циклическое переключение Edit Protocol (xml -> whole_file -> tool_call)
Ctrl+C        Прерывание активной генерации модели (Cancel)
Ctrl+L        Очистка экрана и истории сессии разговора
?             Модальное окно справки (Help)
Esc           Очистить ввод / закрыть модальное окно / отмена
```

### В Model View (Редактор ввода)
```text
Ctrl+Enter    Отправить запрос модели (также Alt+Enter)
Enter         Вставить перевод строки \n (или свернуть/развернуть diff, если ввод пуст)
Ctrl+J        Вставить перевод строки \n
← / →         Перемещение курсора влево / вправо
↑ / ↓         Перемещение курсора вверх / вниз по строкам текста
Ctrl+A / E    Переход в начало / конец строки
Alt+B / F     Перемещение на слово назад / вперед
Ctrl+K / U    Удалить до конца / начала строки в kill-ring
Alt+D / Alt+Bksp Удалить слово вперед / назад
Ctrl+Y        Вставить (yank) удаленный текст из kill-ring
Tab           Вставить 2 пробела отступа
```

### В Model View (Навигация по коду и истории при пустом вводе)
```text
Space / Enter Свернуть / развернуть unified diff выбранного файла
[ / ]         Переход вверх / вниз по списку затронутых файлов
u             Откатить последний AI-коммит (открывает подтверждение)
Ctrl+R        Показать / скрыть ход рассуждений (Reasoning)
PgUp / PgDn   Постраничная прокрутка вывода
Home / End    Переход в самое начало / в самый конец вывода
```

### В Context View
```text
↑ / ↓ (k / j) Навигация по файлам контекста
a             Открыть модальный поиск и добавление файла / glob-маски
e             Сделать выбранный файл EDITABLE (разрешить запись)
r             Сделать выбранный файл READ-ONLY (только чтение)
d / x / Del   Удалить файл из контекста
```

## 9. Никакого arbitrary agent shell в TUI

TUI не создает иллюзии терминального доступа агента к системе. Модель может предлагать только точечные правки в разрешенные файлы и запрашивать запуск зарегистрированных `ProjectAction`.
