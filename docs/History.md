# Семантическая история взаимодействия и компактификация (Semantic Interaction History)

## 1. Назначение и концепция

В отличие от традиционных LLM-интерфейсов, сохраняющих бесконечный плоский лог текстовых сообщений, Tauqe рассматривает взаимодействие с моделью как **цепочку семантических шагов (Semantic Turns)**.

### Ключевые архитектурные принципы:
1. **Git defines reality:** В истории не сохраняются исходные diff'ы, чанки search/replace или сырые XML-блоки. Реальный код изменений хранится в Git-репозитории. В истории сохраняются только чистое пояснение модели, хеш созданного коммита и список затронутых файлов.
2. **Семантическое сжатие ходов (Turn Compaction):** Ответ модели фиксируется как компактный результат: текстовое объяснение + метаданные коммита + список затронутых файлов с префиксами `[NEW]`, `[EDIT]`, `[DEL]`.
3. **Контекстный снимок (Context Snapshot):** Для каждого пользовательского запроса сохраняется список файлов, находившихся в контексте в момент отправки.
4. **Git-события как первоклассные сущности диалога:** Фиксация AI-коммитов и их откат (`undo`) записываются в журнал сессии, благодаря чему модель точно понимает контекст изменений.
5. **Идентичность «диск — промпт»:** Содержимое файла сессии в формате JSON Lines передаётся модели в промпт напрямую внутри тега `<history>` без какой-либо промежуточной переконвертации.

---

## 2. Структура записей семантической истории

### Записи в `HistoryEntry`:
- **`Summary { id, text }`** — сжатое резюме предыдущих ходов после компактификации.
- **`Turn { id, prompt, context }`** — запрос пользователя и список путей файлов в контексте на момент запроса.
- **`Response { id, message, commit, summary, files }`** — ответ модели: очищенное текстовое сообщение, опциональный хеш AI-коммита, саммари и список файлов с типами операций (`[NEW]`, `[EDIT]`, `[DEL]`).
- **`Undo { id, commit, restored_checkpoint }`** — зафиксированный откат коммита с флагом восстановления незакоммиченных изменений разработчика.

### Презентационная модель для клиентов (`UiHistoryItem`):
- `id`: порядковый номер записи;
- `kind`: `User`, `Assistant`, `System`;
- `text`: основной текст;
- `summary`: краткое описание коммита;
- `commit_hash`: хеш AI-коммита;
- `files`: затронутые файлы или файлы контекста.

## 3. Формат персистентного хранения: JSON Lines (`.jsonl`)

История сохраняется в служебной директории проекта `.tauqe/` в едином файле:

```text
.tauqe/
  history.jsonl          # Единая сессия взаимодействия для репозитория
```

Директория `.tauqe/` включается в `.gitignore`.

### Формат строк (JSONL)

Каждая строка представляет собой компактный JSON-объект:

```json
{"type": "summary", "text": "Реализован потоковый XML-парсер, настроена потоковая валидация в памяти."}
{"type": "turn", "prompt": "Добавь обработку тега delete", "context": ["crates/core/src/edits.rs"]}
{"type": "response", "message": "Добавил поддержку тега delete в парсер", "commit": "a1b2c3d", "summary": "Support delete tag in XML parser", "files": ["[EDIT] crates/core/src/edits.rs"]}
{"type": "undo", "commit": "a1b2c3d", "restored_checkpoint": true}
```

*Преимущества:*
- **Append-only:** новые события дописываются в конец файла без риска повредить предыдущую историю.
- **Прозрачность:** файл легко читается стандартными утилитами (`cat`, `jq`).
- **Легковесность:** стандартная сериализация через `serde_json`.

---

## 4. Логирование откатов (Undo)

При выполнении детерминированного отката (`git/undo` в ядре или по клавише `u` в TUI):
- В журнал текущей сессии дописывается событие `undo` с указанием хеша отменённого коммита.
- При последующем запросе модель видит в истории событие отката, что предотвращает повторение отвергнутых решений.

---

## 5. Механизм компактификации (Суммаризация)

С течением времени семантическая история превышает лимиты контекстного окна LLM.
Для контроля объёма используется механизм компактификации на основе **estimated tokens**.

### 5.1 Пороговые значения
- **Лимит истории:** по умолчанию ~8 000 estimated tokens.
- **Хвост истории (Tail):** последние 2–3 хода сохраняются в детальном виде.

### 5.2 Алгоритм сжатия
1. Перед формированием промпта ядро оценивает объём истории (`history_manager.needs_compaction(8000)`).
2. Если порог превышен:
   - Последние $N$ ходов (хвост) отделяются и сохраняются без изменений.
   - Голова истории (старые события и предшествующий summary) отправляется на суммаризацию модели.
   - Сформированное резюме образует новую запись `{"type": "summary", "text": "..."}`.
   - Файл `.tauqe/history.jsonl` атомарно перезаписывается: первой строкой идёт обновлённый `summary`, далее — сохранённые записи хвоста.

## 6. Подача истории в промпт модели

История транслируется модели напрямую из файла сессии путём обрамления содержимого `.jsonl` в тег `<history>`:

```xml
<history>
{"type":"summary","text":"Ранее: реализован потоковый XML-парсер, настроена потоковая валидация."}
{"type":"turn","prompt":"Добавь обработку тега delete в XmlStreamFilter","context":["crates/core/src/edits/stream.rs"]}
{"type":"response","message":"Добавил поддержку тега delete в парсер.","commit":"a1b2c3d","files":["[EDIT] crates/core/src/edits/stream.rs"]}
{"type":"undo","commit":"a1b2c3d","restored_checkpoint":true}
</history>
```

### Преимущества прямой передачи JSONL:
1. **Отсутствие трансляторов:** исключён код преобразования JSONL → псевдо-XML → текст.
2. **Нативное понимание:** современные LLM обучались на гигантских корпусах JSONL и считывают хронологию событий из строковых JSON-объектов.
3. **Нет ограничений API на роли:** исключаются ошибки API-провайдеров при нарушении строгого чередования ролей `user` / `assistant`.
4. **Прозрачность отладки:** ровно то, что сохранено в `.tauqe/history.jsonl`, передаётся модели.

---

## 7. Инварианты

1. **Никаких сырых diff'ов в истории:** история оперирует только хешами коммитов и списками затронутых путей.
2. **Детерминированность лога:** все критические действия (коммиты, откаты, изменения файлов) фиксируются строго по факту их реального завершения в Git и файловой системе.
3. **Единый журнал проекта:** семантическая история хранится централизованно в рамках репозитория в `.tauqe/history.jsonl`.
4. **Один формат везде:** JSONL является форматом и для дискового хранилища, и для инжекции в контекст модели.
