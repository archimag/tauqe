* Overview
Цель плана — довести систему до состояния первичного самообеспечения (Bootstrap Point),
при котором дальнейшая разработка Workbench ведётся внутри самого Workbench.

План построен по принципу вертикальных проверяемых срезов: каждый этап даёт
запускаемый результат, который можно проверить вручную до перехода к следующему.

* Invariants & Constraints
- У модели нет произвольного доступа к shell. Доступны только зарегистрированные проектные действия.
- Git является единственным источником правды о состоянии репозитория и истории.
- TUI общается с ядром строго через протокол (никаких прямых зависимостей от workbench-core).
- Правки применяются детерминированно через атомарный Search/Replace (ровно одно совпадение old_text).
- Протокол взаимодействия строится по принципам SLIME/Swank (семантические события, presentation streams).

* DONE Этап 8. Семантическая история взаимодействия и компактификация (Semantic Session History)
- Суть этапа: Замена плоской текстовой истории диалога на семантическую структуру шагов. Персистентное хранение истории между сессиями в `.workbench/sessions/<branch>.jsonl` в формате JSON Lines (append-only), фиксация ходов пользователя со снимком контекста, компактификация ответов модели (сообщение + хеш коммита + затронутые файлы без сырых diff'ов), логирование Git-событий (коммиты, undo), процедура суммаризации по порогу токенов и прямая подача содержимого JSONL модели внутри тега <history>.
- Структура подмодулей (crates/core/src/history):
  - `crates/core/src/history.rs` — фасад `HistoryManager`: методы фиксации шагов, получения блока `<history>` и запуска компактификации.
  - `crates/core/src/history/entry.rs` — структуры строк JSONL: `Summary`, `Turn` (промпт + пути файлов контекста), `Response` (сообщение + хеш коммита + затронутые файлы), `Undo` (хеш отмененного коммита). Без полей «на будущее».
  - `crates/core/src/history/storage.rs` — персистентное append-only хранилище в `.workbench/sessions/<branch>.jsonl`, чтение и атомарная перезапись файла при компактификации.
  - `crates/core/src/history/compaction.rs` — оценка объема в estimated tokens, разбиение на голову и хвост, вызов суммаризации старых записей.
- Что можно проверить:
  - [X] Семантическая структура истории: события пользователя фиксируют запрос и текущий состав контекста; ответы модели сохраняют объяснение, хеш созданного коммита и список затронутых файлов (без diff'ов).
  - [X] Персистентное хранилище сессий: история сохраняется в `.workbench/sessions/<branch>.jsonl` (или `.workbench/history.jsonl`) в формате JSON Lines (append-only).
  - [X] Логирование Git-событий в историю: успешные AI-коммиты и операции отката (`undo`) детерминированно фиксируются в логе как первоклассные события.
  - [X] Прямая подача истории модели: содержимое активного файла сессии транслируется модели напрямую внутри тега `<history>...</history>` без промежуточной конвертации разметки.
  - [X] Двухуровневая компактификация (суммаризация): при превышении порога estimated tokens (например, > 8000 токенов) история сжимается: хвост последних детальных ходов сохраняется, а старая часть сворачивается в единое резюме первой строкой `{"type": "summary", "text": "..."}`.
  - [X] Персистентность между запусками: сервер сохраняет историю ветки на диск и автоматически загружает её при новом запуске или смене ветки Git.
  - [X] Безопасная очистка истории: нажатие `Ctrl+L` в TUI открывает модальное окно подтверждения (Y/N); при подтверждении сервер очищает файл сессии активной ветки на диске и сбрасывает состояние диалога.

* Post-Bootstrap Backlog (Stage 2)
- Расширение семантического протокола шагов новыми исходами (NeedContext с автоподгрузкой файлов, CodeReview с интерактивными замечаниями).
- Исполнение действий проекта и Evidence (Cargo Actions, Runs & Diagnostics): детекция команд cargo check/test, запуск по горячим клавишам, структурированные диагностики и автоматический сбор ошибок в Evidence.
- Интерактивный сквош серии AI-коммитов (Commit Squash) в Git с автоматической суммаризацией соответствующих ходов сессии.
- Декларативные профили сторонних экосистем (Node/TypeScript/pnpm, Python).
- Голосовой ввод (Voice Ingress, VAD, нормализация транскрипта и распознавание намерений).
- Семантический Repo Map на базе Tree-sitter и PageRank-ранжирование.
- Клиент для Emacs (workbench.el).
- Режим фонового демона (Unix Domain Socket) и одновременное подключение нескольких клиентов.
